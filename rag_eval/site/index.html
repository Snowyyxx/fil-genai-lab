How to Measure RAG

A plain-English, visual guide to the metrics used to tell whether a Retrieval-Augmented-Generation system is actually working.

1. What RAG is (in one picture)

RAG = retrieve relevant documents, then generate an answer using them. You ask a question, a retriever pulls chunks of text from a knowledge base, and an LLM writes an answer grounded in those chunks.

If the answer is wrong, which part failed? The retriever (fetched the wrong chunks) or the generator (had good chunks but hallucinated)? That is exactly why we measure the two halves separately.

2. The two families of metrics

deterministic · no LLM

Retrieval metrics

Grade the documents you fetched. Pure math on rankings. Needs gold labels: for each question, which document IDs are truly relevant.

Hit RateMRR Precision@kRecall@k NDCG@k
LLM-as-judge · Claude

Generation metrics

Grade the answer itself. A strong model (Claude) reads the question, context, and answer and scores them. Mirrors the RAGAS metric set.

FaithfulnessAnswer Relevancy Context RelevanceAnswer Correctness
Rule of thumb: retrieval metrics are cheap, exact, and need labels. Judge metrics need no labels (mostly) and catch hallucination — but cost an API call and have some variance. Use both.

3. Retrieval metrics — did we fetch the right docs?

Setup for every example below: the retriever returned 3 docs in this order, and only D1 is truly relevant.

Retrieved (rank order): [ D3 , D1 , D9 ]
Relevant (gold): { D1 }
using the metrics 
from rag_eval import retrieval_metrics as rm

retrieved = ["D3", "D1", "D9"]   # ranked output of your retriever
relevant  = {"D1"}               # gold labels for this question

rm.hit_rate(retrieved, relevant, k=3)          # 1.0
rm.reciprocal_rank(retrieved, relevant)        # 0.5   (D1 at rank 2)
rm.precision_at_k(retrieved, relevant, k=3)    # 0.333
rm.recall_at_k(retrieved, relevant, k=3)       # 1.0
rm.ndcg_at_k(retrieved, relevant, k=3)         # 0.631

Hit Rate@k — "did we get anything useful?"

1 if at least one relevant doc is in the top-k, else 0. The most forgiving metric.

D1 is in the top-3 → Hit Rate@3 = 1.0

MRR — "how early did the first good doc appear?"

Reciprocal Rank = 1 ÷ (position of the first relevant doc). Averaged over all questions this is Mean Reciprocal Rank. Rank 1 → 1.0, rank 2 → 0.5, rank 3 → 0.33…

First relevant doc (D1) is at position 2 → RR = 1/2 = 0.5
retrieval_metrics.py — implementation 
def hit_rate(retrieved, relevant, k=None):
    relevant = set(relevant)
    topk = retrieved if k is None else retrieved[:k]
    return 1.0 if any(d in relevant for d in topk) else 0.0

def reciprocal_rank(retrieved, relevant):
    relevant = set(relevant)
    for i, d in enumerate(retrieved, start=1):   # 1-indexed ranks
        if d in relevant:
            return 1.0 / i                       # first hit only
    return 0.0

Precision@k vs Recall@k — the core trade-off

Precision@k

Of what we showed the LLM, how much was relevant?
relevant in top-k ÷ k Low precision = noise in the prompt.

1 relevant out of 3 shown → 0.33

Recall@k

Of everything relevant, how much did we fetch?
relevant in top-k ÷ all relevant Low recall = missing support.

Found the 1 relevant doc → 1.0
retrieval_metrics.py — implementation 
def precision_at_k(retrieved, relevant, k):
    relevant = set(relevant)
    topk = retrieved[:k]
    if not topk:
        return 0.0
    hits = sum(1 for d in topk if d in relevant)
    return hits / len(topk)          # relevant shown / total shown

def recall_at_k(retrieved, relevant, k):
    relevant = set(relevant)
    if not relevant:
        return 0.0
    hits = len(set(retrieved[:k]) & relevant)
    return hits / len(relevant)      # relevant found / all relevant

You tune k (how many chunks to retrieve) and add a re-ranker to push both up at once.

NDCG@k — "are the good docs ranked high?"

Precision and recall ignore order within the top-k. NDCG does not: a relevant doc earns more credit the higher it ranks, discounted by log₂(position+1), then normalized against the perfect ordering so the score lands in 0–1.

DCG = Σ relevance(i) / log₂(i + 1) (i = rank) IDCG = same, but with all relevant docs ranked first NDCG = DCG / IDCG
D1 (relevant) is at rank 2 → DCG = 1/log₂(3) = 0.63.
Ideal: D1 at rank 1 → IDCG = 1/log₂(2) = 1.0.
NDCG@3 = 0.63 / 1.0 = 0.63 — good, but it'd be 1.0 if D1 were ranked first.
retrieval_metrics.py — implementation 
import math

def ndcg_at_k(retrieved, relevant, k):
    relevant = set(relevant)
    topk = retrieved[:k]

    # DCG: each relevant doc scores 1, discounted by its rank position
    dcg = sum(
        (1.0 if d in relevant else 0.0) / math.log2(i + 1)
        for i, d in enumerate(topk, start=1)
    )

    # IDCG: the best possible ordering (all relevant docs first)
    ideal_hits = min(len(relevant), k)
    idcg = sum(1.0 / math.log2(i + 1) for i in range(1, ideal_hits + 1))

    return dcg / idcg if idcg > 0 else 0.0      # normalize to 0..1
Context Precision (in the RAGAS set) is a cousin of NDCG: it averages the precision measured at each rank where a relevant doc sits, so it also rewards putting relevant docs early.

4. Judge metrics — is the answer any good?

These use an LLM (here, Claude) as an examiner. The big win: most need no gold labels, so you can run them on live traffic. The star metric is Faithfulness — your hallucination detector.

Faithfulness — is every claim backed by the context?

The judge breaks the answer into atomic claims, then checks each one against the retrieved context only (its own knowledge doesn't count). Score = supported claims ÷ total claims.

context?} C1 --> J C2 --> J J -->|yes| S1["✓ Claim 1 supported"] J -->|no| S2["✗ Claim 2 NOT in context"] S1 --> SC["Score = 1 of 2 = 0.5"] S2 --> SC style A fill:#2a2119,stroke:#e08a5b,color:#e6e8ec style CTX fill:#12151b,stroke:#262b36,color:#9aa3b2 style J fill:#1d2733,stroke:#6ea8fe,color:#e6e8ec style S1 fill:#181b22,stroke:#5bd08a,color:#e6e8ec style S2 fill:#181b22,stroke:#e06b6b,color:#e6e8ec style SC fill:#181b22,stroke:#e08a5b,color:#e6e8ec
Context: "Hamlet is a tragedy written by William Shakespeare."
Answer: "Hamlet was written by William Shakespeare in 1601."
Claim "by Shakespeare" → supported. Claim "in 1601" → not in context (the model made it up).
Faithfulness = 1/2 = 0.5. The number pinpoints the hallucination.
calling the judge 
from rag_eval import ClaudeJudge

judge = ClaudeJudge()   # reads ANTHROPIC_API_KEY (or an `ant auth login` profile)

result = judge.faithfulness(
    question="Who wrote Hamlet?",
    contexts=["Hamlet is a tragedy written by William Shakespeare."],
    answer="Hamlet was written by William Shakespeare in 1601.",
)

print(result.score)     # 0.5
print(result.reason)    # "1 unsupported claim(s): written in 1601"
for c in result.claims: # inspect *why* — the audit trail
    print(c.supported, "|", c.claim)
# True  | Hamlet was written by William Shakespeare
# False | Hamlet was written in 1601

Answer Relevancy — does the answer address the question?

Clever trick: the judge reverse-generates the questions the answer would perfectly answer, then measures how close those are to the real question. A rambling or off-topic answer produces mismatched questions → low score, even if it's factually true. Evasive answers ("I don't know") score 0.

REAL question?} Q2 --> M Q3 --> M M --> SC[Average = score 0–1] style A fill:#2a2119,stroke:#e08a5b,color:#e6e8ec style M fill:#1d2733,stroke:#6ea8fe,color:#e6e8ec style SC fill:#181b22,stroke:#e08a5b,color:#e6e8ec

Context Relevance — how much retrieved text was actually useful?

The judge counts what fraction of the retrieved context is relevant to the question (signal vs. noise). Like Precision@k, but judged directly from the question — no gold labels needed.

2 context chunks retrieved, only 1 is on-topic → Context Relevance = 0.5. Tells you your retriever is padding the prompt with junk.

Answer Correctness — does it match the reference answer?

The only judge metric that needs a ground-truth answer. The judge compares facts (not wording): correct = 1.0, partially correct = 0.5, incorrect = 0.0.

Reference: "Hamlet was written by William Shakespeare."
Answer: "Hamlet was written by Shakespeare in 1601." → core fact agrees, extra unverified detail → partially correct = 0.5.
Under the hood each judge call uses Claude Opus 4.8 with structured outputs — so it must return the claims / questions / verdicts in a fixed schema. That's why you can read why a sample scored what it did, not just the number.
llm_judge.py — under the hood 
from pydantic import BaseModel, Field
import anthropic

# 1. Define the schema Claude MUST fill in — one row per atomic claim.
class Claim(BaseModel):
    claim: str
    supported: bool = Field(description="True if the context supports this claim.")

class FaithfulnessResult(BaseModel):
    claims: list[Claim]
    @property
    def score(self):                       # supported / total
        return sum(c.supported for c in self.claims) / len(self.claims)

client = anthropic.Anthropic()

# 2. messages.parse() forces the reply into the schema — no JSON hand-parsing.
resp = client.messages.parse(
    model="claude-opus-4-8",
    max_tokens=4096,
    thinking={"type": "adaptive"},          # let it reason before deciding
    output_config={"effort": "high"},       # judging is intelligence-sensitive
    system="Extract atomic claims from the ANSWER and mark each as supported "
           "by the CONTEXT alone (ignore outside knowledge). Be strict.",
    messages=[{"role": "user",
               "content": f"CONTEXT:\n{context}\n\nANSWER:\n{answer}"}],
    output_format=FaithfulnessResult,       # <-- the schema
)

result = resp.parsed_output                 # a validated FaithfulnessResult
print(result.score)

Run every metric over a dataset in one call

evaluate.py — the full pipeline 
from rag_eval import RAGSample, evaluate_dataset

samples = [
    RAGSample(
        question="Who wrote Hamlet?",
        answer="Hamlet was written by William Shakespeare in 1601.",
        contexts=["Hamlet is a tragedy written by William Shakespeare."],
        retrieved_ids=["doc_hamlet", "doc_globe"],  # enables retrieval metrics
        relevant_ids=["doc_hamlet"],                # gold labels
        ground_truth="Hamlet was written by William Shakespeare.",  # optional
    ),
]

result = evaluate_dataset(samples, k=5)     # retrieval + judge metrics
print(result["aggregate"])
# {'hit_rate@k': 1.0, 'mrr': 0.5, 'faithfulness': 0.5, ...}

# Free mode — deterministic metrics only, zero API calls:
evaluate_dataset(samples, k=5, run_llm_metrics=False)
